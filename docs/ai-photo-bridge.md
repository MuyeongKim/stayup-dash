# AI 사진 후보 파일 연계

2026-10-18 사용자 승인. 현장별 같은/다른 PC 구성을 지원하기 위해 공통 파일 전달을 기본으로 한다. 온라인 지도 작업 기준점 `210c3be`(v1.2.7) 이후에 추가했다. 같은 PC의 사진 폴더 자동 읽기는 2단계로 추가했다. PC 간 실시간 전송·실시간 이벤트 자동 연계·좌표 OCR은 후속이다.

## 운용과 보존

- AI-page의 작업 결과·이전 후보 확인창에서 `stayup-ai-candidates.json`을 내보내고, STAY UP의 **AI 후보 불러오기**로 현재 상황에 추가/갱신한다. 상황 전체 백업 복원과 별도이며 현장명과 신규/갱신 수를 확인한다.
- 영구 작업 UUID + 후보 ID가 식별자다. 동일 리비전·동일 내용은 중복 반영하지 않는다. 과거 리비전과 같은 리비전의 다른 내용은 거부한다.
- 원본의 판정·시각·GPS·이미지를 갱신하되 상황판의 대응 상태·메모·대응시각·기존 이력은 유지한다. 새 원본에서 빠진 후보도 `원본에서 빠진 후보`로 보존한다.
- 지도는 사진 촬영 지점이며 같은 사진의 후보는 묶는다. 좌표 없음·지도 미보정·범위 밖은 목록에 표시한다. 기존 발견 핀·수색 완료·발견 경보는 바꾸지 않는다.
- 이미지 본체는 기존 IndexedDB 블롭 저장소에 두고 상태·창간 동기화에는 참조만 둔다. 이미지 GC·전체 JSON 백업·복구·완전삭제에 포함한다. 기존 조작·표출 창은 모두 연계 버전으로 다시 연다.

## 공통 형식 v1

- `format: stayup-ai-candidates`, `version: 1`, `generatedAt`(시간대 포함), `app: {name, version}`.
- `run: {id, revision, status, photoCount, completedCount, failedCount}`. UUID와 리비전은 원본 기록에서 보존한다.
- `candidates`: `id`, `photoId`, `file`(파일명만), `capturedAt`(null·시간대 미상 보존), `gps`(null 또는 `{lat, lon}`), `locationKind: photo_gps`, `confidence`, `review`, `box`, `imageSize`, `thumbnail`(null 또는 JPEG data URL).
- 파일 16 MiB, 후보 5,000건, JPEG 한 장 32 KiB·최대 512px. 전체 상황은 작업 500개까지. 파일·숫자·위경도·ID 중복·JPEG 헤더와 실제 디코딩을 검증한 뒤 원자적으로 반영한다. 전체 상황 백업은 기존 24 MiB 한도를 유지한다.
- 두 저장소의 `tests/fixtures/stayup-photo-candidates-v1.json`은 같은 생산자/소비자 계약 예제다. 원본 절대 경로·성명·온라인 지도 인증키는 후보 파일에 넣지 않는다.

## 검증

브라우저 회귀검사는 `tests/ai-candidates.js`를 기존 `tests/regression.html`에 포함한다. 기존 상황/이력 보존, 중복·과거·충돌 갱신, 대응 보존, 입력 취소·잘못된 데이터·저장 실패·늦은 파일 완료, 이미지 GC·백업/복구·좌표·같은 사진 묶음·온라인 지도 투영·390px 화면·이미지 삭제를 확인한다.

브라우저 **350/350 통과**(기존 315 + 연계 35), 기존 온라인 지도 SDK 계약 검사 **18/18 통과**, JS 구문·버전 일치·자동 버전 스크립트 구문·diff 검사를 통과했다.

실제 로컬 YOLO26x/CPU로 사진 4장(성공 3·실패 1)을 처리해 만든 9개 후보를 GUI에서 내보냈다. 판정 변경·반복·폴더 복사에서 리비전 `[1, 2, 2, 2]`와 같은 작업 UUID를 확인했다. 상황판의 실제 파일 선택으로 9개를 가져와 기존 상황·기체 3대·기록 10개를 보존했고, 대응 메모를 저장한 뒤 리비전을 갱신·반복·과거 파일로 재시도했다. 최종 백업에는 후보 9개·이미지 9개·리비전 2·보존한 대응 메모·이력 13개가 포함됐다. 조작/표출 두 창의 판정·대응 갱신도 확인했다.

새 브라우저 저장소에서 복사한 후보 JSON만 가져오는 방식으로 별도 PC 구성을 재현했다. 미리보기 9장이 디코딩되고, 같은 파일 재전달 후에도 그 저장소의 대응 메모를 유지했다. 이는 실제 두 대의 물리 PC·기관망 인수시험을 대신하지 않는다. 온라인 지도는 모의 SDK로 투영을 확인했으며 실제 공급자 키를 사용한 연결은 이번 변경에서 검증하지 않는다.

사용설명서에 별도 AI 후보 장을 추가하고 HTML/PDF를 재생성해 렌더링을 확인했다. 로컬 실행 증거는 `/tmp/stayup-photo-bridge`에 보관한다. `board-backup.json`은 가상 상황과 실제 공개 샘플 탐지 결과를 결합한 검증용 파일이다.

Google Chrome의 `file://` 직접 실행에서도 후보 파일을 가져와 이미지 9개를 읽고 대응 메모를 저장한 뒤 새로고침해 동일한 메모·리비전 2가 유지되는 것을 확인했다. UI 없는 영상에서 좌표 OCR을 수행하거나 EXE를 만드는 작업은 포함하지 않는다.

원본 분석의 부분 완료·실패·취소와 성공/실패 수를 가져오기 확인창·후보 목록의 작업 정보에 표시한다. 이전 저장본에 통계가 없으면 0으로 추정하지 않고 미상으로 표시한다.

## 같은 PC 폴더 연계 2단계

사용자 승인(2026-10-18)으로 수동 파일 방식에 자동 읽기를 추가했다. AI-page V26.1018의 작업 결과에서 **상황판 자동 저장 폴더 연결**을 누르면 사진 분석 종료·이전 사진 기록 열기·판정 저장 때 작업별 `stayup-ai-candidates-<작업 UUID>.json`을 원자 저장한다. 진행 중 분석·실시간 영상은 포함하지 않는다. 반복 내용은 파일을 다시 쓰지 않으며 더 최신/동일 리비전 충돌 파일을 덮지 않는다.

상황판의 **자동 읽기 폴더 연결**로 같은 폴더를 선택·확인한다. Chromium File System Access의 읽기 전용 권한으로 약 2초마다 바로 아래 `stayup-ai-candidates.json` 또는 작업 UUID별 파일을 읽는다. 하위 폴더·다른 이름·임시 파일은 제외한다. 후보 파일 최대 500개, 합계 64 MiB, 개별 16 MiB, 전체 후보 5,000건·작업 500개 제한을 유지한다. 폴더에는 후보 파일만 보관한다.

폴더명·마지막 확인시각·반영/오류 수를 표시한다. 개별 손상·과거·충돌 파일은 거부하고 정상 파일은 계속 반영한다. 폴더 자체 오류/권한 회수/편집권 상실은 연결을 해제한다. 새로고침·상황 전체 복원·초기화·수동 후보/지도 불러오기 후 다시 연결한다. 경로/핸들은 영구 저장·백업·창간 전송하지 않는다. 미완료 비동기 읽기도 연결 해제 후에는 반영하지 않는다.

폴더에서 파일이 사라져도 기존 후보·대응·이력을 삭제하지 않는다. 중복 내용은 상태나 타임라인을 늘리지 않는다. 수동 가져오기·백업/복구·오프라인/온라인 지도 흐름과 병행한다. 연결 폴더 파일은 상황판의 개인정보 완전삭제 대상에 포함되지 않으므로 따로 정리한다.

실행 조건은 Chrome·Edge의 파일 직접 실행 또는 HTTPS·localhost다. 브라우저 백그라운드·절전에서는 주기가 지연될 수 있다. [Chrome 공식 권한 안내](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access), [showDirectoryPicker 읽기 권한](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)을 따른다.

회귀검사 `tests/ai-folder.js`와 실제 디스크 검사 `tests/ai-folder-browser.mjs`를 추가했다. 실제 디스크 검사는 CDP의 디렉터리 드롭으로 네이티브 `FileSystemDirectoryHandle`을 얻고, 폴더 선택 함수의 반환값만 그 핸들로 대체한다. 이후 권한·디렉터리 순회·파일 읽기·원자 교체 감지는 실제 Chrome/디스크를 사용한다. OS 폴더 선택창 자체와 Windows EXE·물리 캡처보드 인수시험은 별도다.

2단계 최종 검증: 전체 브라우저 **399/399**, 폴더 실제 디스크 검사 로컬 HTTP·file:// 각각 **11/11** 통과. 기존 온라인 SDK 18·지역 지도 엔진 18·오프라인 재시작 11개 통과. macOS 탐지 GUI(YOLO26x/CPU)와 Chrome 동시 실행에서 사진 4장(성공 3·실패 1)의 후보 9개 자동 전달, 판정 저장 리비전 1→2, 기존 상황·대응 메모 보존을 확인했다. 두 프로그램의 연결 해제·안전 종료와 안내 PDF(상황판 17쪽)를 확인했다. 실행 증거는 `/tmp/stayup-folder-bridge`에 보관한다.
