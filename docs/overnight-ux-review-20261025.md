# STAY UP 야간 사용성 개선 기록

기간: 2026-10-25 야간부터 2026-10-26 10:00까지, Asia/Seoul.

사용자가 정한 1사이클은 `직접 실행 → 처음 사용자의 업무 흐름 수행 → 불편·디자인 문제 재현 → 수정 → 같은 흐름과 필요한 회귀 검사로 확인`이다. 이 기록은 자동화·도구를 사용한 검토이며 실제 직원 대상 사용성 평가로 표현하지 않는다.

## 진행 원칙

- 실제 브라우저 프로필·출동 자료 대신 별도 주소 또는 임시 브라우저 컨텍스트의 가상 데이터만 사용한다.
- 재현되는 문제를 우선 수정한다. 변경이 없으면 확인한 시나리오와 근거만 기록하고 버전을 올리지 않는다.
- 기록·사진·지역 지도·복구·안전 판단 경계와 기존 기능을 보존한다.
- 실질 변경은 관련 사용설명서와 검증을 함께 마무리하고 GitHub 자동 버전 후 최신 커밋·태그를 GitLab에 동기화한다.
- 09:45부터 새 변경을 시작하지 않는다. 10:00에 개선을 종료하고 최종 상태를 보고한다.

## 사이클 01 — 상황에서 인원·기체 등록까지

상태: 구현·직접 동선 재검증 완료. 기준 버전 v1.2.16. 원격 반영 버전·SHA는 이후 Git 기록으로 확인한다.

- 재현 환경: 별도 로컬 주소 `127.0.0.1:18869`, 실제 프로그램을 in-app browser로 실행. 상황명 `야간 UX 검토용 가상 상황`, 인원 별칭 `조종 A`.
- 직접 수행: 첫 화면 → 새 상황 시작 → 상황명·장소 입력 → 다음: 실종자 → 다음: 인원 → 인원 추가·별칭 입력 → 다음: 드론 → 기체 추가.
- 확인한 문제: 인원·기체 추가 뒤 포커스가 추가 버튼에 남는다. 새 항목의 입력 위치를 다시 찾아야 하며, 기체의 조종자 별칭도 명부를 보고 다시 타이핑해야 한다.
- 이번 수정 범위: 인원 추가 시 새 성명 입력으로, 기체 추가 시 새 조종자 입력으로 이동. 등록된 조종자 별칭은 명시적인 표준 선택 메뉴로 제공하고 직접 입력과 기존 명부 검증을 유지한다. 읽기 전용 상태에서는 선택 메뉴도 비활성화한다.
- 직접 재검증: 두 번째 인원 추가 후 새 성명 칸에 실제 포커스가 놓임을 확인했다. 분리된 연습에서 네 번째 기체를 추가한 뒤 조종자 입력에 포커스가 놓이고, `4호기 등록 조종자 선택`에서 `홍○○`를 골랐을 때 입력칸에도 같은 값이 반영됨을 확인했다. 모두 가상 데이터다.
- 자동 검증: HTTP·파일 직접 실행 각각 35/35 통과. 추가된 검사는 새 인원 포커스, 기체 포커스·고정 영역 아래 노출, 명부 선택과 직접 입력 경로 보존이다. 기존 전체 회귀 411/411, 실제 화면·데이터 보존 85/85도 통과했다.
- 스크린샷: `assets/readme/pilot-roster-preview.png`. 자세한 임시 검증 산출물: `/tmp/stayup-overnight-20261025/cycle01/`.

## 사이클 02 — 읽기 전용 창의 안내와 보기 테마

상태: 구현·직접 실행·회귀 재검증 완료. 기준 버전 v1.2.17.

- 재현: 임시 Chrome 컨텍스트에서 가상 상황을 소유한 창을 둔 채 같은 상황을 새 창으로 열었다. 읽기 전용의 처음 사용 안내와 주간·야간 버튼이 모두 비활성화되어 있었다. 수정 전 관측 결과는 `guide=false, theme=false`였다.
- 문제 원인: 업무 편집을 잠그는 컨트롤 목록에 업무 상태를 변경하지 않는 새 안내·테마 버튼이 포함되어 있었다.
- 수정: 안내 열기·접기와 보기 테마 버튼만 허용했다. 새 상황·불러오기 버튼은 안내 재생성 때에도 읽기 전용이면 비활성화하며, 불러오기 이벤트 처리에서도 편집권을 다시 확인한다. 읽기 전용 안내 문구에 가능한 보기 동작을 명시했다.
- 재검증: 실제 Chrome에서 안내 열기·접기, 야간 전환과 복귀, 메뉴 이동을 수행했다. 업무 입력·기체 추가·명부 선택은 잠겨 있고 소유 창과 읽기 전용 창의 상태·리비전·활동 기록이 동일하게 유지되는 것을 확인했다. 편집권도 이동하지 않았다. 소유 창의 입력 갱신으로 안내를 다시 생성해도 편집 버튼은 계속 잠겨 있었다.
- 전용 검사: `tests/readonly-view-browser.mjs`, HTTP·파일 직접 실행 각각 13/13 통과. 기존 전체 회귀 411/411, 화면·데이터 보존 85/85, 새 사용자 검사 35/35도 통과했다.
- 화면: [읽기 전용 안내와 테마](../assets/readme/readonly-view-preview.png). 검증 산출물: `/tmp/stayup-overnight-20261025/cycle02/`.

## 사이클 03 — 실종자 기본 입력과 계산 가정 분리

상태: 구현·동선·재시작·회귀 재검증 완료. 기준 버전 v1.2.18.

- 재현: 별도 Chrome 컨텍스트에서 파일을 직접 열고 실종자 메뉴로 이동했다. 기본 화면의 이름 라벨은 `성명`이고 별칭 예시는 없었으며, 보행속도·감쇄계수가 바로 노출되어 있었다. 감지기 착용 정보도 같은 계산 설정 줄에 있었다.
- 수정: `식별명(별칭)`과 `대상 A` 예시를 제공했다. 숫자 계산 설정과 설명은 기본 접힘 상세로 이동하고 감지기 착용은 기본 화면에 남겼다. 상세 제목에 현재 보행속도·계수를 표시한다. 기존 저장 필드·값·계산식은 변경하지 않았다.
- 재검증: 상세를 열기만 해서는 상태가 바뀌지 않고, 탭 이동 시 열어 둔 상세와 값이 유지됐다. 별칭 `대상 A`, 가상 사용자 설정 3.3km/h·0.45, 감지기 표시를 입력하고 다시 연 뒤에도 그대로 남았다. 320/390px에서 가로 넘침과 기본 입력 접근을 확인했다.
- 검사 보정: 재시작 후 소유 창의 정상 기상 자동 조회가 `weather.*`와 리비전을 갱신하는 것을 필드 비교로 확인했다. 이 갱신을 연습 조작의 영향으로 잘못 판정하지 않도록 테스트의 가상 소유 상황에서 자동 조회를 끄고 모든 상태 필드에 대한 보존 비교는 유지했다. 실제 프로그램의 자동 기상 동작은 바꾸지 않았다.
- 자동 검사: HTTP·파일 직접 실행 각각 42/42, 기존 전체 회귀 411/411, 화면·데이터 보존 85/85 통과.
- 화면: [실종자 기본 입력](../assets/readme/subject-basic-preview.png). 수정 전후·모바일·진단 산출물: `/tmp/stayup-overnight-20261025/cycle03/`.

## 사이클 04 — 낮은 휴대 화면의 입력 가림

상태: 구현·낮은 화면·작성 중 축소·회귀 재검증 완료. 기준 버전 v1.2.19.

- 재현: 별도 Chrome 컨텍스트, 390×400 화면, 80자 가상 우선 지시. 메뉴에서 상황을 선택하고 Tab으로 상황명에 이동했다. 고정 공통 영역이 높이 321.5px을 차지했고 상황명 입력칸의 위쪽 38.5px/전체 44px이 그 아래에 가려졌다. 기존 버전 태그로도 같은 문제를 재현했다.
- 수정 방향: 낮은 화면에서는 안전 사유와 메뉴를 간결하게 고정하고, 우선 지시 원문은 `현재 지시` 버튼으로 접근한다. 원문은 삭제·축약하지 않으며 일반 높이에서는 기존 전체 공통 영역 고정을 유지한다. 긴급 유인기 사유도 고정 안전 상태에 표시한다.
- 기술 기준: [W3C 초점 가림 설명](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), [Chrome의 키보드·뷰포트 조정 안내](https://developer.chrome.com/blog/viewport-resize-behavior/). 지원하는 브라우저에 레이아웃 조정 힌트를 제공한다. 실제 물리 휴대폰 키보드 검증은 아니다.
- 검증: 390×400·320×400·844×400에서 입력칸 전체가 상하 고정 영역 사이에 놓임을 확인했다. 원문 전체·포커스 접근, 보기 조작 중 데이터 보존, 유인기 즉시 착륙 사유 표시, 일반 높이 복귀도 통과했다. 작성 중 높이가 줄어 텍스트 영역이 화면 밖으로 밀리는 사례를 추가 재현하고 입력 위치만 보정하도록 했으며 내용·커서·리비전은 보존됐다.
- 회귀: 화면·데이터 100/100(기존 85 + 신규 15), 전체 411/411, 새 사용자 42/42, 읽기 전용 HTTP·파일 각각 15/15 통과. 일반 휴대 화면에서 단축 버튼이 메뉴를 가리지 않는 CSS 우선순위도 확인했다.
- 화면: [낮은 입력 화면](../assets/readme/compact-input-preview.png). 원본 지시는 별도 버튼으로 그대로 볼 수 있으며 안전 계산은 바꾸지 않았다.
- 산출물: `/tmp/stayup-overnight-20261025/cycle04/`. `before-app/`은 재현용 이전 버전 HTML이며 제품 파일을 교체한 것이 아니다.

## 사이클 05 — 자동 보관의 첫 다운로드와 상태 표시

상태: 구현·직접 동선·회귀·설명서 검증 완료. 기준 버전 v1.2.20. 원격 반영 버전·SHA는 이후 Git 기록으로 확인한다.

- 재현: 별도 주소 `127.0.0.1:18875`의 가상 상황에서 새 상황 시작 → 상황명 입력 → 데이터 메뉴를 수행했다. 첫 안내에는 브라우저 저장만 설명됐고, 파일 미지정 시 첫 변경 확인 때 시작하는 자동 다운로드는 설명되지 않았다. 상단이 `보관 방금 · 다운로드`로 바뀐 뒤에도 데이터 메뉴 옆은 `자동 보관 대기 · 다운로드`로 남았다.
- 기준과 결정: 기존 주간 카드·파란 선택·주황 주요 동작을 유지한다. Refero의 제품 문구 원칙인 `위치·상태·다음 행동`에 따라 보관 방식·첫 요청 시점·실제 파일 확인을 설명하고, 기존 데이터 메뉴로 이동하는 버튼만 추가한다. 다운로드 요청을 파일 보관 완료로 표현하지 않는다.
- 수정: 시작 안내에서 약 30초 변경 확인과 최초·이후 다운로드 주기를 설명한다. 파일 미지정 경로와 새로 열 때 재지정하는 절차를 데이터 메뉴에 명시한다. 상단·설정의 상태를 함께 갱신하며 지정 파일 쓰기와 다운로드 요청을 구분한다. 자동 보관 기본값·주기·파일 내용·저장 구조는 바꾸지 않았다.
- 직접 재검증: 같은 가상 상황을 다시 열고 처음 사용 안내 → 보관 설정·백업으로 이동했다. 데이터 메뉴가 선택되고 제목으로 초점이 이동하며 기존 상황명이 남았다. 다음 자동 확인 뒤 상단과 설정 옆이 모두 `다운로드 요청 1분 전 · 파일 확인`으로 일치했다. 실제 파일 선택 권한을 새로 부여하지 않았다.
- 검증: 새 사용자 HTTP·파일 직접 실행 각각 50/50, 화면·데이터 100/100, 전체 회귀 411/411, 읽기 전용 15/15 통과. 실제 JSON 다운로드와 내용·리비전 보존, 가상 파일 핸들 쓰기 완료와 상태 구분, 320/390px 설명·버튼 배치, 연습 안내 분리를 확인했다. 가상 파일 핸들 검사는 물리 디스크 권한·저장 실패에 대한 실기 검증을 뜻하지 않는다. 사용설명서 MD·HTML·PDF와 화면 예시를 갱신하고 PDF 21쪽 중 변경된 3·4·18·19쪽을 직접 렌더링해 배치·캡션을 확인했다.
- 화면: [시작 안내](../assets/readme/first-use-preview.png), [보관 상태](../assets/readme/backup-status-preview.png). 임시 산출물: `/tmp/stayup-overnight-20261025/cycle05/`.

## 사이클 06 — 사진 지도 위 구역명·담당의 야간 대비

상태: 구현·직접 실행·회귀·설명서 재검증 완료. 기준 버전 v1.2.21. 원격 반영 버전·SHA는 이후 Git 기록으로 확인한다.

- 재현: 분리된 연습 공간, 1600×900 가상 체크무늬 사진, 1366px → 390px → 320px의 실제 Chrome에서 보기·칠하기·키보드 핀·큰 지도·Esc를 수행했다. 야간 테마의 밝은 사진 위에서 구역명이 흐릿했다. 미수색 글자는 `rgba(233,240,247,.62)`, 별도 글자 받침·그림자는 없었다.
- 기준과 결정: [W3C 글자 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)와 Refero의 정보 밀도가 높은 화면의 명도 대비 원칙을 적용한다. 기존 핀 라벨과 같은 작은 짙은 받침을 구역명·담당 글자 뒤에만 둔다. 상태 채움·무늬·팔레트·사진 불투명도·좌표·저장 형식은 유지한다.
- 이미 확인한 동작: 보기 모드 클릭은 기록을 바꾸지 않았고, 완료 칠하기는 선택 칸에 반영됐다. 방향키·Enter로 최종목격 핀을 놓고 Esc로 대기 중 배치를 취소한 뒤 한 번 더 눌러 큰 지도를 닫을 수 있었다. 닫으면 여는 버튼으로 초점이 돌아왔다. 스크린샷·검사 산출물은 `/tmp/stayup-overnight-20261025/cycle06/`에 남긴다.
- 수정·재검증: 구역명과 담당에 불투명한 작은 받침을 적용했다. 좁은 칸에서 두 글자가 겹치는 것을 재현한 뒤 세로로 나누고, 쓸기 취소로 부분 복원할 때도 같은 표시를 유지했다. 기존 상태 색·무늬와 채움 농도는 그대로다. 네 상태를 실제 팔레트로 칠한 뒤 1366·390·320px에서 글자들이 겹치거나 칸 밖으로 나가지 않는 것을 확인했다.
- 자동 검사: `tests/map-label-browser.mjs` HTTP·파일 직접 실행 각각 18/18. 주간·야간과 농도 0·100%의 글자·받침 계산 대비는 17.499:1이다. 실제 키보드·포인터 조작, 취소 전후 전체 JSON·리비전 보존, 큰 지도 초점 복귀와 표출 주간·야간도 확인했다. 기존 자료에서 갱신한 화면·데이터 100/100과 전체 회귀 411/411 통과. 물리 휴대폰·모니터 거리나 앱 전체의 WCAG 적합성을 검증한 결과는 아니다.
- 화면·설명서: [네 상태의 구역명·담당](../assets/readme/map-labels-preview.png), 수정 전후와 320/390px·표출 스크린샷은 위 임시 산출물에 보관했다. Markdown·HTML·PDF를 갱신하고 21쪽 PDF의 변경된 지도 장 10~12쪽을 렌더링해 예시·캡션·본문 배치를 확인했다.

## 사이클 07 — AI 후보 대응 입력의 저장 전·후 구분

상태: 구현·직접 실행·회귀·설명서 재검증 완료. 기준 버전 v1.2.22. 원격 반영 버전·SHA는 이후 Git 기록으로 확인한다.

- 재현: 별도 주소 `127.0.0.1:18877`의 연습 공간에서 가상 후보 파일을 불러와 첫 후보 대응 메모를 입력했다. 상단은 `저장·복구 정상`이고 후보 카드에는 입력이 저장 전이라는 표시가 없었다. `대응 저장`을 누르지 않고 새로고침하면 메모가 사라졌다. 기존 방식상 이 입력은 별도 저장 버튼으로 기록하는 초안이다.
- 기준과 결정: 기존 밝은 카드·상태색 의미와 Refero의 `위치·상태·다음 행동` 문구 원칙을 유지한다. 저장 정책을 바꾸거나 새 저장 필드를 만들지 않고, 카드에 현재 대응 입력의 미저장 여부와 다음 동작을 명시한다. 후보별 입력 변경 때 해당 표시만 갱신하여 포커스·커서를 유지한다.
- 수정 범위: 대응 저장이 필요한 입력과 저장된 대응 기록의 시각을 구분하고, 메뉴 이동 중 초안 유지와 창 재시작 시 소실 범위를 설명한다. 후보 원본 판정·대응 상태·발견 경보·수색 상태·저장 구조는 바꾸지 않는다. 산출물은 `/tmp/stayup-overnight-20261025/cycle07/`에 기록한다.
- 직접 재검증: 같은 가상 후보에서 입력하자 `대응 미저장`이 나타났다. 대응 상태를 `지상팀 통보`로 선택하고 저장한 뒤 `저장된 대응 기록 · 10-26 02:39`로 바뀌었다. 다시 열어도 입력한 메모·상태·시각을 유지했다.
- 자동 검사: `tests/ai-response-browser.mjs` HTTP·파일 직접 실행 각각 18/18 통과. 초안 입력·커서, 원래 값으로 되돌리기, 메뉴·필터·사진 확인 왕복, 다른 후보와의 구분, 320/390px·주야간, 저장공간 실패 모의·재시도와 이력 중복 방지, 재시작·읽기 전용을 확인했다. 저장 복원으로 객체 키 순서가 달라지는 것은 내용 손실과 구분하며 모든 상태 필드의 값을 재귀 비교했다. 기존 자료에서 갱신한 화면·데이터 100/100과 전체 회귀 411/411도 통과했다. 실제 직원 사용성 평가·물리 기기·보조공학 기기 시험은 아니다.
- 화면·설명서: [대응 입력과 미저장 상태](../assets/readme/ai-response-preview.png). 가상 예시의 본문·화면을 설명서 MD·HTML·PDF에 반영하고 22쪽 PDF의 변경된 16~18쪽을 렌더링해 확인했다. 인쇄 예시는 브라우저의 3배 픽셀 캡처를 사용하고 QA 화면의 좌표 검사는 CSS 픽셀을 유지했다.

## 사이클 08 — 과거 기록의 쪽 이동·정정 후 확인 위치

상태: 구현·직접 실행·회귀·설명서 재검증 완료. 기준 버전 v1.2.23. 원격 반영 버전·SHA는 이후 Git 기록으로 확인한다.

- 재현: 별도 주소 `127.0.0.1:18878`의 연습에서 가상 기록 25개를 만들고 검색했다. 키보드 Enter로 다음 쪽을 열자 초점이 `BODY`로 사라졌다. 그 쪽의 기록을 사유와 함께 정정한 뒤에는 검색 결과가 아닌 즉시조작 제목으로 초점이 돌아갔으며, 제목 위치는 화면 위 -64.8px로 고정 영역 아래에 가려졌다.
- 기준과 결정: Refero의 초점 유지 원칙과 이미 적용한 입력 위치 이동 방식을 사용한다. 쪽 이동·검색 결과에서 정정/취소를 마친 뒤 결과 요약을 고정 영역 아래에 놓고 초점을 옮긴다. 검색 입력 중에는 초점을 옮기지 않는다. 색은 기존 테마의 정보색을 사용하고 기록·필터·정정·취소의 저장 및 감사 이력 방식은 유지한다.

- 추가 재현·수정: 정정 사유 입력창에서 취소해도 `감사기록을 위해 사유가 필요합니다`라는 오류 안내가 다시 떴다. 입력창 취소는 그대로 중단하고, 공백 사유를 실제 제출할 때만 기존 사유 검사를 유지했다.
- 직접 재검증: 같은 가상 기록을 다시 검색했다. 입력창 취소는 prompt 한 번으로 종료됐고, 정정을 마치면 `검색 27건 / 전체 39건 · 2 / 2쪽` 결과 요약으로 초점이 돌아왔다. 요약은 고정 공통 영역 아래에 보이며 정정본과 원문·사유도 남았다.
