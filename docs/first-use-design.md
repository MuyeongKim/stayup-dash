# 첫 사용 안내와 주간·야간 화면 보완

2026-10-25. 기존 STAY UP에 사용자가 승인한 밝은 조작 화면·준비 안내·분리된 연습 방향을 적용했습니다.

## 화면 기준

| 결정 | 기준 | 적용 |
| --- | --- | --- |
| 밝은 조작 화면 | 사용자 가독성 피드백과 기존 STAY UP 입력 탭 구조 | 밝은 회색 바탕, 흰 입력 영역, 진한 글자, 파란 선택 표시 |
| 테마별 컨트롤 | 기본 날짜 아이콘이 어두운 바탕에서 검게 남는 실제 화면 | `color-scheme`, 입력 글자 16px, 설명 14px 이상 |
| 기존 색의 의미 유지 | STAY UP의 경보·주의·완료 표시 | 주황은 주요 동작, 파랑은 선택·정보, 빨강·노랑·초록은 상태에 사용 |
| 준비 현황과 다음 행동 | [GOV.UK Task list](https://design-system.service.gov.uk/components/task-list/)와 [W3C 단계별 입력](https://www.w3.org/WAI/tutorials/forms/multi-page/) | 기존 입력 위치로 연결하는 네 단계 안내. 전체 안내를 접거나 메뉴를 직접 선택할 수 있음 |
| 글자 대비 | [W3C Contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 주요 입력 글자와 라벨의 실제 Chrome 계산 색 대비 4.5:1 이상 검사 |

사진이나 브랜드를 바꾸는 작업은 포함하지 않았습니다. 사용자가 승인한 기존 파란 탭·주황 동작 버튼·카드 구조를 유지했습니다. 정상 입력 현황은 실제 비행 승인으로 표시하지 않습니다.

## 데이터와 보기 상태

- 테마 선택은 `stayup.view.v1`에 별도로 보관하며 업무 상태·내보내기 형식·리비전을 바꾸지 않습니다.
- 기존 실제 상황의 `stayup.dash.*`, 사진 DB `stayup.dash`, 지역 지도 DB `stayup-offline-regions-v1`은 그대로 사용합니다.
- 연습은 `stayup.practice.*`, 사진 DB `stayup.practice`, 지역 지도 DB `stayup-practice-offline-regions-v1`을 사용합니다. 잠금·세대·복구·지도키·보기 설정도 실제 상황과 분리합니다.
- 연습 표출은 별도 창 이름과 메시지 표식을 사용합니다. 실제 상황은 연습 메시지를 받아들이지 않습니다. 이전 버전의 실제 상황 메시지는 기존처럼 처리합니다.
- 연습은 외부 기상 자동 조회·실제 자동 보관 파일·AI 자동 읽기 폴더 연결을 사용하지 않습니다. 수동 입력·사진·격자·기체·기록·연습 백업은 사용할 수 있습니다.
- 새 상황 시작은 기존 내용이 있으면 백업 다운로드와 사용자 보관 확인, 복구점 생성 뒤 수행합니다. 취소·실패 시 현재 내용을 유지합니다.

## 검증

- `tests/layout-browser.mjs`: 이전 버전 저장 자료 복원, 85개 화면·데이터 보존 검사와 기존 회귀 411개.
- `tests/usability-browser.mjs`: 안내 경로·테마·입력 대비·시작 취소·파일 선택·연습 분리·삭제 후 실제 및 연습 자료 보존 검사. 임시 Chrome 컨텍스트를 사용합니다.
- `tests/offline-engine.mjs`, `tests/offline-browser.mjs`: 지역 지도 저장 18개, 실제 브라우저 종료 후 오프라인 재시작 11개.
- 테스트의 상황·지도·인원은 가상 데이터입니다. 실제 직원의 첫 사용 성공률이나 실제 모니터·프로젝터 가독성을 측정한 결과는 아닙니다.

실제 사용 확인 시 처음 접하는 직원에게 설명 없이 `상황 만들기 → 인원·기체 등록 → 지도 준비 → 구역 표시 → 백업`을 진행하게 하고 막힌 위치를 기록합니다.
