# 처음 사용하는 직원을 위한 이름·작업 순서 개편

## 목표와 기준

사용자가 요청한 기준은 프로그램 구조를 공부하지 않아도 준비부터 백업까지 다음 행동을 알 수 있게 하는 것이다. 기존 밝은 입력 화면·파란 선택 표시·주황 주요 동작을 유지한다. Refero 도구가 없어 로컬 `refero-design`의 copywriting·craft-details 지침과 현재 실행 화면을 기준으로 삼았다.

| 결정 | 근거 | 적용 |
| --- | --- | --- |
| 직원이 하려는 일로 이름 짓기 | 사용자 요청, copywriting의 행동+대상 원칙 | 상황 백업 저장·백업 파일 열기·수색 기록·현황 화면 |
| 한 번에 현재 할 일만 설명 | 첫 실행에서 안내가 입력칸을 화면 아래로 밀어냄 | 짧은 현재 단계 안내, 현재 순서만 먼저 표시하고 전체 입력 현황·자동 백업 설명은 펼쳐 보기 |
| 마지막을 백업으로 연결 | 기존 다음 순서는 기록에서 처음으로 돌아감 | 상황→대상자→인원→드론→지도→안전→기록→백업 |
| 순서와 실제 확인 구분 | 기존 안전 판단과 저장 경계를 유지해야 함 | 8단계는 이동 순서, 4개 입력 현황과 실제 비행승인은 별도 |
| 파일 요청 결과 알리기 | 다운로드 요청만으로 실제 보관을 확정할 수 없음 | 내려받기 요청·파일 확인 안내, 입력 변경 시 다시 백업 안내 |

## 보존 범위

- 저장 키·상태 버전·필드·JSON 형식·파일 확장자·사진/지도/후보 저장 구조는 바꾸지 않는다.
- 기존 메뉴와 버튼의 내부 ID·동작 식별자를 유지한다. 추가 기능도 계속 접근할 수 있다.
- 새 상황·불러오기·복구·완전 삭제 확인, 편집권과 실제/연습 분리, 안전 판단은 유지한다.
- 현재 단계·안내 펼침·백업 요청 상태는 화면 또는 세션의 보기 상태이며 업무 자료에 저장하지 않는다.

## 검증 목록

- 새 프로필: 첫 안내→상황→대상자→인원→드론→지도→안전→기록→백업을 실제 입력·클릭으로 수행.
- 이전/다음·메뉴 왕복 중 입력과 작성 중 기록/후보 대응 메모 보존.
- 마지막 단계에서 실제 파일 다운로드와 전체 자료 비교. 요청 표시를 파일 보관 완료로 표현하지 않음.
- 새 상황 취소·불러오기 취소·읽기 전용·연습 복귀 시 기존 자료와 권한 보존.
- 기존 버전 자료 업그레이드, 320/390px·노트북·대형 표출·주야간에서 실제 화면 검토.
- 사용설명서 MD·HTML·PDF, README와 관련 화면 예시를 실제 이름에 맞춤.

실제 직원 관찰 평가와 Windows·물리 휴대폰·표출장비 실기 검증을 대신하는 결과로 표현하지 않는다.

## 적용한 주요 이름

| 이전 | 변경 |
| --- | --- |
| 즉시조작 | 수색 기록 |
| 데이터 | 백업·설정 |
| AI 후보 | 탐지 사진 |
| JSON 내보내기 / JSON 불러오기 | 상황 백업 저장 / 백업 파일 열기 |
| 지도 파일 내보내기 / 가져오기 | 지도 백업 저장 / 열기 |
| 표출 화면 / 조작 패널 | 현황 화면 / 입력 화면 |
| 편집권 가져오기 / 읽기 전용 | 이 창에서 입력하기 / 보기 전용 |
| 전체 초기화 / 선택한 복구본 적용 | 현재 상황 비우기 / 선택한 시점으로 되돌리기 |
| 이력만 기록 / 금일 소티 | 기록 남기기 / 오늘 비행 횟수 |

인원·드론 메뉴는 등록 후 교대·운용도 계속 다룰 수 있도록 `인원 관리`·`드론 관리`로 표시한다. 센서·비행/구역 상태 코드, 저장 파일 확장자와 이전 기록에 들어 있는 문장은 바꾸지 않는다.

## 검증 결과

- `tests/beginner-flow-browser.mjs`: HTTP·파일 직접 실행 각각 27/27. 빈 작업에서 이전·다음으로 8개 화면을 거쳐 사진·인원·드론·기록을 포함한 실제 백업 파일을 만들고 모든 값을 비교했다. 재백업 안내·실패·재시작·메뉴 왕복 보존도 확인했다.
- `tests/usability-browser.mjs`: 각각 58/58. 안내 펼침, 새 작업/불러오기 취소, 실제·연습의 사진·권한·표출·삭제 분리를 유지했다.
- `tests/readonly-view-browser.mjs`: 각각 21/21. 보기 전용에서 가능한 기능, 원본 보호와 명시적 입력권 전환을 확인했다.
- `tests/layout-browser.mjs`: 기존 v1.2.38 자료 업그레이드·화면·데이터 100/100, 전체 기존 회귀 411/411. 메뉴 순서와 첫 화면에 맞춘 기대값을 갱신하고 기존 키보드·초점·기록·저장 조건은 유지했다.
- 지역 지도 오프라인 재시작 20/20, 파일 직접 실행의 사진·복구·작업 분리 21/21, 배터리·기체 작업 33/33도 통과했다.
- 320/390px·노트북의 현재 할 일과 백업 버튼, 주간/야간과 대형 현황 화면을 확인했다. 일반 주요 버튼과 인원·드론 추가는 44px 이상의 높이로 확보했다.
- 설명서 MD·HTML·PDF와 현재 입력·백업·보기 전용·지도/탐지 사진 예시를 갱신했다. 과거 버전이라고 표시한 지도·표출 예시는 그 설명을 유지했다. 27쪽 PDF를 렌더링해 확인했고 등록 선택 그림만 남던 불필요한 별도 쪽을 줄였다.

이 검토는 가상 자료와 임시 Chrome 프로필을 사용했다. 실제 사용자 브라우저 저장소·출동 자료·시스템 클립보드는 건드리지 않았다. 검증 원본은 `/tmp/stayup-beginner-ux/`에 보관한다.

## 추가 사이클: 준비부터 백업까지 다시 실행

사용자의 추가 요청으로 v1.2.39를 별도 Chrome 프로필에서 열고, 화면의 이름만 따라 새 수색 준비 → 가상 상황·대상자 → 조종자 → 드론 연결 → 가상 사진 지도 → 안전 미확인 유지 → 메모 기록 → 백업 저장 → 같은 파일 다시 열기를 수행했다. 자동 검사를 실제 직원 관찰 평가로 해석하지 않는다.

| 재현된 문제 | 최소 수정 | 다시 확인한 결과 |
| --- | --- | --- |
| 1366×768에서 빈 지도 격자만 먼저 보이고 사진 넣기 버튼은 아래에 있어 첫 동작을 찾기 어려움 | 기존 사진 넣기 버튼을 격자 위로 이동. 기존 지역 지도 준비 안내를 여는 바로가기 추가 | 1366×768·390×844·320×800에서 두 버튼이 상하 고정 영역 사이에 먼저 보임. 각 버튼 높이 44px 이상 |
| 붙여넣기 설명이 격자 뒤로 겹쳐 읽기 어려움 | 설명을 지도 위 준비 도구로 모으고 격자 속 중복 안내 제거 | 지도 미적용 상태와 격자 라벨은 유지하며 설명 겹침 해소 |
| 사진 배경도 `사진·오프라인`으로 표시되어 `저장한 지역 지도`와 혼동 가능 | 사진 배경 이름을 `지도·현장 사진`으로 변경 | 내부 `image`·`offline` 값과 연결·보호 조건은 그대로 유지 |
| 수색 기록의 첫 유형이 `AI 후보`여서 일반 메모도 후보 기록으로 분류될 수 있음 | 첫 화면의 기록 유형만 `특이사항`으로 선택 | 실제 메모는 `note`로 기록. 사용자가 고른 열원감지·작성 중 문장은 메뉴 왕복 후에도 보존 |

지역 지도 바로가기는 준비 안내를 열고 해당 위치로 이동할 뿐, 범위 생성·지도 저장·업무 자료 변경을 실행하지 않는다. 큰 지도에서 바로가기를 눌렀을 때 모달이 남아 안내를 가리던 동작도 재현해 수정했다. 큰 지도는 닫히고 준비 안내에 초점을 연결한다. 파일 직접 실행에서는 기존 HTTPS/localhost 필요 안내를 유지한다.

수정 후 새 임시 프로필에서 같은 작업 순서를 다시 수행했다. 실제 내려받은 백업은 사진과 기록을 포함한 전체 내보내기 값과 일치했다. 다시 열기 후 업무 값·사진·기록을 비교해 보존을 확인했다. 복원 처리에 따라 `meta`와 사진의 `grid.mapId/mapVer`가 갱신되는 기존 동작은 비교에서 구분했다. 승인 미확인은 끝까지 미확인으로 남겼다.

- 준비→백업 검사: HTTP·파일 직접 실행 각각 **35/35**.
- 기존 자료 업그레이드·화면·자료 검사: **101/101**, 기존 회귀 **411/411**.
- 파일 직접 실행의 새 상황·백업·복구·연습 분리 검사: **58/58**.
- 실행 화면·실제 가상 백업·재현 결과: `/tmp/stayup-first-employee-review-20261026/`. 수정 전 `04-grid-before.png`, 수정 후 `09-grid-after-1366.png`·`10-grid-after-390.png`·`12-grid-after-320.png`, 직접 실행 결과 `manual-walkthrough.json`.

실제 직원 관찰과 Windows·물리 장비 검증은 추가로 필요하다. 이 사이클은 출동 자료와 실제 사용자 프로필을 사용하지 않았다.
