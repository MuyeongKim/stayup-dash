판독성 검증

CP 천막에서 대형 모니터를 보는 거리는 2~4m입니다. 세 방향은 취향이 아니라 아래 실측치에 대한 서로 다른 대응입니다.

1 · 시야각 — 3m 에서 읽히는 것은 네 개뿐

55인치 1080p 기준(화면 폭 1218mm, 1px = 0.634mm). 시야각 5 arcmin은 식별 한계, 16 arcmin은 흘려봐도 읽히는 선입니다. 현행 표출 화면의 요소를 환산하면:

2 · 1px 테두리는 3m 에서 존재하지 않는다

1px = 0.634mm 이므로 3m 에서 0.73 arcmin입니다. 식별 한계(5′)의 1/7입니다. 대비를 얼마로 올려도 안 보입니다. 그루핑은 선이 아니라 면으로 해야 합니다.

5 · 세 방향 — 같은 측정에 대한 서로 다른 답

방향 A

현행 정제

구조는 그대로. 실측으로 드러난 결함만 고칩니다. 정보는 하나도 빠지지 않습니다.

하는 일
  • --muted2 → #7E93AA (5.70:1)
  • --danger → #FF6B61 + 채움 패널
  • 반경 16종 → 3단 (4 / 2 / 999px) + 원형 표식 50%
  • 부제 0.98 → 1.13rem, 타임라인 1.02 → 1.25rem
  • 면(surface)을 한 단 올려 테두리 의존을 줄임
대가 32px 선은 여전히 못 넘습니다. 2m 용 화면이 조금 더 잘 읽히는 것뿐입니다. 실측에서 1080p 에 다 들어가지 않아 격자에 최소 높이를 걸고 타임라인을 4줄로 줄여야 했습니다.
방향 B

2단 시야

보는 거리가 둘이라는 사실을 설계에 반영합니다. 원거리 존과 근거리 존을 나누고 라벨로 명시합니다.

하는 일
  • 원거리 존: 값 32px 이상, 라벨 18px 이상, 테두리 0
  • 근거리 존: 기록자용. 한 단 어둡게 눌러 시선에서 뺌
  • 인상착의를 글자에서 대형 색면으로 — 3m 에서 색은 읽힘
  • 격자 셀 ID 1.18 → 2.00rem (담당 표기는 근거리 정보로 1.25rem)
  • 정보 손실 없음. 배치만 재편
  • 원거리 존 실측: 18px 미달 0건 · 32px 이상 22개. 22px 구간의 실종시각·최종목격은 골든타임 KPI와 지도 핀으로 이미 원거리에 표현돼 있어 중복 표기로 둠
대가 레이아웃이 크게 바뀝니다. 근거리 존이 좁아 타임라인이 6줄로 줄어듭니다.
방향 C

원거리 전용

조작 패널 상단에 KPI 줄이 생겼으니, 대형 모니터는 더 이상 기록자를 섬길 필요가 없습니다. 방 안의 사람만 봅니다.

하는 일
  • 32px 미달 요소를 줄이지 않고 지움
  • KPI 4.30 → 5.50rem, 격자 셀 → 2.50rem
  • 인원 명부 · 센서 · 소티 · 기상 상세 · 좌표는 조작 패널로
  • 타임라인은 최근 3건만
대가 정보가 실제로 빠집니다. 기록자 옆의 두 사람이 인원·기상 상세를 보고 싶을 때 노트북을 봐야 합니다.

세 아트보드는 1920×1080 프레임에 넣고 브라우저에서 잘림을 실측했습니다 — 넘침 0, 잘림 0, 생략(…) 0. 폰트는 Noto Sans KR(앱의 실제 폴백 체인)입니다.
환산 전제 — 55인치 16:9, 1920×1080, 대문자/한글 높이 = 글자 크기 × 0.70, 1rem = 16px @1920×1080. 다른 크기 모니터에서는 화면 폭 비율로 비례합니다(예: 43인치는 1.28배 더 가까이 봐야 같은 시야각).
